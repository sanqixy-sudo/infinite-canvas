# 短剧制作开发路线

## 目标与取舍

以“项目 → 分集 → 场次 → 镜头 → 候选版本 → 成片 → 团队审片”为业务主线。夸我用于对照短剧生产和团队功能；LibTV 用于借鉴创作上下文、面板布局、顺序预览和就近操作。保留小盟的品牌、中文文案与深浅主题。

- 优先完成从剧本到交付的实际流程。参考功能必须落到数据保存、权限、失败处理和具体入口。
- 不做作品广场。专业多轨剪辑、实时多人同屏、动捕和自研模型训练暂缓。
- 复用已有裁剪、宫格切图、遮罩、批量图片、节点引用、平台模型、账号文件和钱包能力。
- 当前四个特殊渠道模型继续固定 **720×1280**。P5已实现独立的多规格配置与发布能力；不会自动修改这四个渠道或增加未配置的可用模型和价格。

## 1. 剧本到镜头

1. 我的项目 → 项目详情 → **短剧制作** → 启用制作计划。
2. 创建分集、剧本、场次；项目资产记录角色、场景、道具、声音、风格及其变体。
3. **AI 拆镜**选择已开放的平台文字模型与目标镜头数，界面显示调用价格。使用现有平台文字调用和服务端扣费，不向浏览器下发供应商 Key。
4. 返回后先预览：逐条修改画面、对白、运镜、时长、场次与资产，勾选需要的镜头，确认后追加到本集。
5. AI 不直接改画布、不覆盖已有镜头。未采用草案按账号/项目/分集保存到 localforage；关闭可恢复，采用前先持久化制作草稿。生成期间剧本/资产变化时要求重新核对。
6. 镜头放入画布建立说明、图片、视频和参考连线。创建节点不调用模型、不扣费；已有完整绑定定位原镜头，失效绑定需确认重建。
7. 进入画布按模型能力生成；从结果建立独立候选节点，图片/视频分别选择采用。文件复用，不重复上传；原生成节点换结果不影响已保存候选。

AI 每次最多拆 40 镜头，计划时长仍是创作安排，具体生成受模型能力约束。停止请求不保证上游尚未执行；不自动付费重试。AI 拆镜的文字调用仍走既有账号流水，**不分摊进某个图片/视频镜头成本**。

## 2. 任务队列与成本

- 画布图/视频任务首次创建时，将当时已保存的镜头绑定冻结到独立生产历史；后续解绑、改名或短期任务清理不会把历史移给别的镜头。
- 列表按分集、任务状态分页，可见页面定期刷新。成本汇总针对当前分集全部已记录任务，不受当前页和状态筛选影响。
- 同一任务关联多个镜头时，分集总额只计一次；镜头明细各显示该任务，不能再把明细相加当总成本。
- 金额从服务端实际扣退流水汇总；明确 0、未知、待用量、待补扣分别展示。输入/输出 Token 保持缺失与零的区别，预扣不能冒充最终成本。
- 普通任务流水使用 `image:<id>` / `video:<id>` / `audio:<id>`，避免同账号不同类型同编号串账；网关保留自身稳定任务 ID。逐镜配音的`production_voice_*`任务须属于当前账号的项目和镜头，创建后同样冻结历史；任务清理不删除真实费用。
- 只有网关明确失败且已完成释放/结算、原镜头仍绑定时可在队列重试。先重新报价、显示本次预扣，确认后提交；可勾选本页失败任务逐项提交，发生异常停止后续。团队审批任务除外，须回团队项目重新申请审批；撤销共享或清理短期任务后也不能绕过审批直接重试。
- 每笔重试的 requestId 在请求前持久化。超时/刷新沿用原 ID 查询和恢复，已受理的父任务不能再分叉重试；需要再次重试时操作最新失败项。未知提交绝不自动当失败重投。
- 普通非网关图/视频任务返回原画布确认参数后发起新任务，逐镜配音返回镜头配音区；它们不通过网关重试入口自动重放。未知配音先恢复原ID查看状态，再由用户明确停止或确认新的生成。
- 历史只覆盖功能启用后、任务发起时已保存的镜头关联，不猜测回填更早记录。此汇总不是完整账号账单，也不包含未关联生成、文字拆镜或存储费用。
- 当前普通任务启动恢复以单 API 容器为部署边界；进程中断且无法安全恢复时标记未知。网关按已有持久轮询恢复。多 API 副本的普通同步执行需另加执行租约。

## 3. 分集交付

### 顺序预览与素材包

“分集交付”按镜头顺序预览已采用视频或图片，提供就近上一镜/下一镜/播放控制。图片按计划秒数，视频预览原素材实际时长；导出 MP4 才按计划裁剪和拼接。

ZIP 包含真实账号素材、交付音轨原文件、JSON/Markdown 清单和可选 SRT。相同文件只下载一次，最大 256 MiB；清单保留音轨起点、裁切、音量与字幕时间表，SRT 优先使用编辑版本，否则按镜头对白生成草稿。ZIP 可交接当前草稿，并明确标记其状态；原文件不预混或裁切。仅有供应商外链的素材先保存到账号文件，避免链接失效和越权抓取。

### 逐镜配音、声音与字幕

1. 保存镜头后选择平台音频模型、语音和语速，编辑本镜对白；明确确认模型和本次最高算力才发起生成。复用现有音频渠道，服务端保留密钥，费用超过确认上限时拒绝调用。
2. 请求编号在提交前写入账号/项目/分集隔离的本机记录。超时、刷新恢复同一请求，服务端按账号和完整请求内容去重；不同参数不能复用原编号。没有自动付费重试。中断且无法确认的任务标未知，核对任务与费用后再主动新建。
3. 配音实际保存到账号文件后加入镜头音轨，记录保留到计划已保存；也可选择本项目账号音频或上传 MP3/WAV 等文件。单文件最多 64 MiB、浏览器可读时长最多 60 分钟；关联镜头用于定位起点，不自动生成口型。
4. 单集最多 64 段音轨，可设置片中起点、源文件截取起点、使用时长、音量及原声音量，允许重叠播放。浏览器试听单轨，最终混音查看真实 MP4。最近 20 次编辑可撤销；移除音轨保留原账号文件。修改镜头顺序或时长后需核对时间位置。
5. 单集最多 500 条字幕、单条最多 500 字，可手动拆条/编辑/定位，或将整段镜头对白按镜头时长、第一条关联音轨的实际截取范围对齐；无配音时沿用镜头时长。这不是语音识别或逐字时间推断。
6. 字幕可导出 SRT，或勾选烧录后通过 FFmpeg 字幕滤镜嵌入画面。中文字体、白字深色描边为固定样式，文本中的 ASS 控制字符转义，不接收用户滤镜或执行命令。

### 异步 MP4

1. 先保存制作计划；提交时冻结其 revision、镜头顺序、采用版本、秒数、音轨和字幕编辑。存在未保存修改时不能发起新成片，重试始终使用原任务快照。
2. 图片/视频/音轨必须是本人账号文件，服务端核对文件、候选身份和当前保存版本。音轨按保存的时间表截取、延迟并混入原声；实际源音频时长不足时拒绝。
3. 当前输出为 720×1280、24fps、H.264/AAC；保持原比例补边，不拉伸。图片补计划时长；视频裁到计划时长，原片过短直接报错，不静默复制帧或变速。
4. 每集最多 60 镜头、300 秒、单镜最多 60 秒；输入合计 512 MiB、成片最多 256 MiB、单音轨文件最多 64 MiB。每账号最多 2 个在途，数据库租约保持全局串行合成。
5. 任务页展示排队/处理/完成/失败，支持取消、失败重试、刷新找回未知提交。取消未知提交写入同 requestId 的取消记录，阻挡晚到提交重新入队。
6. 成片保存为账号文件并按实际大小占用空间，使用原文件权限预览和下载。合成本身不调用模型或新增算力扣费；主动配音属于已确认的模型调用，另按实际流水记账。
7. 运行环境需要 `ffmpeg`、`ffprobe`、字幕滤镜、中文字体及 fontconfig，Dockerfile 已加入依赖。只处理平台下载到临时目录的文件，固定 argv 和本地文件协议、限制线程/超时/大小；不任意读取用户 URL。实际无模型样例已通过，仍需复杂真实素材与部署环境验收。
8. 重试输出使用独立对象键，旧 worker 不覆盖新成片。物理上传前持久化意图；完成时在同一事务确认有效租约、登记文件/容量并移除意图。服务恢复会复查无索引意图，跳过有效执行或已索引对象，只清理同一存储身份和当前尝试的对象；存储配置变更时保留待处理记录。
9. 清理墓碑保留并定时复查，处理旧 worker 迟到上传；不把未入库成片当作完成。仍需实测强杀窗口、R2 延迟写入、存储配置变化和容量预留。已保存计划音轨、运行快照和其他未解除引用分别阻止文件删除。

当前为轻量声音/字幕编排与固定竖屏成片，不包含专业剪辑器、ASR 逐字字幕、口型生成或实时混音预览。真实无模型FFmpeg小样本回归已执行通过，核对画幅、时长、双音轨延迟与中文烧录像素，本次未跳过。

## 4. 团队协作与审批

- 工作台增加“团队协作”。创建团队，生成 24 小时有效的一次性邀请码；本人复制给受邀人，系统不自动发送外部消息。数据库只保存码哈希。
- 角色为所有者、管理员、成员。只有所有者管理管理员；管理员不能更改所有者或其他管理员权限。普通成员可参与审片。
- 发布者明确选择**自己已保存**制作计划中的分集；默认不分享整集剧本，可主动勾选。服务器构建只读镜头快照，仅包括镜头文字与已采用账号素材。
- 分享不会授予私人画布、其他分集、账号素材库或钱包访问权。修改个人计划不自动改已发布版本，需要再发布新版本。
- 团队按冻结镜头留言；本人、发布者或管理者可按权限删除意见。撤销分享、移除发布者或删除团队后，服务端拒绝继续读取该版本与其媒体。
- 媒体通过同源鉴权接口逐次检查团队成员身份，支持 Range，不发可脱离成员权限使用的长期链接；响应为 private/no-store。已经下载或缓冲的内容无法撤回。
- 未撤销审片引用的文件阻止物理删除；先撤销版本，再按普通文件引用报告处理。

### 共享制作计划与素材

原项目拥有者明确共享已保存计划，选择是否允许成员编辑。共享编辑包括剧本、分集、场次、镜头和角色设定，使用原计划revision CAS；冲突提示加载新版本，本机草稿保留。成员只能提交白名单文本字段，服务器保留私人画布绑定、候选结果和交付轨道。已有条目删除及镜头跨集移动由原拥有者处理。私人画布不变为团队同屏画布。

成员可以从自己的账号文件中逐项共享图片、视频和音频；库中只显示明确共享项，不遍历他人的私有文件。共享资产与审片媒体使用同源鉴权Range流；撤销、退出或成员移除后，新请求立即核验并拒绝。活跃共享资产阻止物理删除；活跃共享计划须先撤销共享才能删除个人制作计划。

### 所有权与成本权限

团队所有者输入完整确认文字后，可转交给当前成员，原所有者成为管理员。这只转移团队管理权，个人项目/文件所有权及付费账号保持原归属。所有者可授予普通成员成本查看权限；团队所有者、管理员和项目原拥有者具有对应项目成本权限，未授权成员的响应不含金额。管理者可分页查看事务内操作审计；实际资金流水仍在原付款账号。

### 生成申请、预扣与预算

1. 原拥有者先在个人制作计划中保存镜头与视频节点绑定，再共享计划并设置审批预算。
2. 成员从团队项目发起镜头申请，选择已发布平台视频模型、受支持的参数和团队共享素材；申请本身不调用模型、不扣费。
3. 原项目拥有者获取报价，核对预扣和输入/输出Token或秒/次费率，再明确确认扣自己的个人算力。团队所有者变更不会把费用改扣到新所有者。
4. 服务端在团队→付款者锁内重新检查成员、共享、模型版本、镜头绑定、素材和预算；预算占用、个人预扣、流水、任务及视频节点绑定同事务写入。重复申请/批准沿用同一ID，回滚时没有部分扣费。
5. 节点仅更新执行信息与本次参数，保留原提示词、媒体及位置；已有运行任务时拒绝覆盖。旧画布保存不得清除活跃团队任务，打开原画布后继续显示进度和结果。
6. 完成后按冻结规则和实际任务用量结算，少用退回、多用补扣，未知用量等待核实。补扣余额不足时挂起待补扣，不能把未知费用显示为免费。
7. 预算只统计本审批入口任务；普通个人画布创作自行付费、不计团队预算。最终实际费用可能超过预扣和预算，超支后阻止后续批准，预算不是费用硬封顶。
8. 撤销成员或共享阻止新审批；已受理任务产生的费用仍归原付款者结算。权限撤销不能抹去已有账务，也不能撤回已下载媒体。

P4自动回归、隔离HTTP权限检查与桌面审批入口检查已通过，线上已登录团队页可用；团队空列表分页已修正，待最终镜像复核，真实渠道和长期并发仍待验收。没有共享钱包、自动划转余额、私人画布共同编辑或实时同屏。当前操作审计记录关键业务写入，资金对账使用个人流水与审批任务记录。验收矩阵见[待测试](../progress/pending-test.md#p4-团队协作与生成审批)。

## 5. 标准模型与多规格路由

### 管理员配置与发布

1. 中间件中创建标准模型，填写公开名称和真实业务分组，再增加真实可用规格。标准模型ID是画布标识；上游模型ID在每个规格的私有路由里填写，可与展示名称完全不同。
2. 每个规格填写分辨率、比例、时长区间、参考场景、生成音频条件、图片/视频/音频上限、协议与渠道。两条规格不能同时匹配同一组参数；不能唯一确定时拒绝提交，不静默切渠道。
3. 设置原价：Token总量或输入/输出不同价，或按秒、按成功次。每档均可区分有/无参考视频；按秒须明确请求时长或响应实际时长，按次只在成功时计1次。
4. 原价/能力/路由改动使用新revision并确认发布。画布后台同步目录，核对后选择原价倍率或逐规格固定算力售价，另填公开名称、徽标和备注，再发布给用户。
5. 以上同协议配置操作无需重建容器。增加新的供应商协议仍要开发和部署相应适配器；不把任意接口、无真实配置的规格或未经验证的价格展示成可用。

### 用户选择与计费

- 模型弹窗按真实分组展示标准名称及各规格价格/素材上限；选择分辨率时联动可用比例、时长和音频条件，参考素材变化时重新校验。原四个特殊渠道仍固定720×1280。
- 生成前由服务端解析唯一规格并报价，冻结规格ID、版本、单位、数量来源、预扣量及售价；提交再次检查规则是否变化。模型或价格改变后需要新报价确认，已受理任务不受影响。
- 中间件保存实际渠道、上游ID和密钥快照，画布保存计价快照。任务结束按冻结单价与真实用量结算差额；缺Token分项或实际时长就保留待核对，不默认0或改用估算。
- 同requestId优先恢复既有任务，禁止未知提交换ID自动重投；失败且费用明确的任务才能按P2流程重新报价。秒/次和Token的单位、预扣、实扣在历史中分别展示。

### 当前协议边界

| 适配器 | 当前可配置范围 | 需要人工确认 |
| --- | --- | --- |
| 小盟NewToken专用插件 | 原四个Seedance模型，固定720p + 9:16，Token总量或分项 | 真实渠道用量、输入/输出原价、参考视频档位；插件0.2.2不因此放宽规格 |
| Seedance原生任务协议 | 已核实采用`/api/v3/contents/generations/tasks`结构的真实规格/别名 | 上游实际支持的能力与计费单位、成功/失败及用量字段 |
| NewToken第三方按秒协议 | `/v1/videos`、`reference_*`、`ratio`；单一720p或1080p、4～15秒 | 每个上游ID的固定分辨率/音频输出及按请求时长单价；不适用于官方`extra_*`混合计费协议 |

这些能力已通过本轮自动检查，尚未对新真实渠道进行付费联调。具体证据与未验场景见[待测试](../progress/pending-test.md#p5-标准模型多规格路由与定价)。
