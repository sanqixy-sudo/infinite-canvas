# Seedance 分组接入与计费交付

## 本次范围

画布前端 → 画布平台后端（报价、预扣、结算）→ 独立模型中间件 → 用户的 New API 专用插件 → NewToken 原生任务接口。

接入四个 `doubao-seedance` 型号：`2-0-260128`、`2-0-fast-260128`、`2-0-mini-260615`、`2-5-260628`。当前交付插件0.2.2，各模型独立Token计价、固定720×1280竖屏。初版按任务返回的`usage.total_tokens`结算，0.2.0增加`input_output_tokens`分项模式，0.2.1修正导入示例数量。不读供应商账单，不按输出时长猜最终Token，也不从总量减输出推算输入。包含分项代码的`split-5c917bd9159d`为历史部署版本；本轮集中检查快照为`70c8270ac599`，追加空队列查询修正及定向Go检查后，两服务已再次构建并部署`production-0df20ae25d24`，真实计价仍待联调。

## 模型能力与价格

- 画布分组名为“特殊分组”，插件名为“newtoken 特殊渠道 · 720×1280”。四模型均只开放`720p`和`9:16`，不再根据其他渠道能力开放1080p或横屏；插件和服务端均校验此限制。
- 原生参数传`resolution: "720p"`、`ratio: "9:16"`，不把`720*1280`填入resolution。已有中间件配置须在新版管理页核对后保存，再在画布同步发布；没有后台自动改写数据库。
- 2.0 系列 9 图/3 视频/3 音频、4–15秒；2.5 为30图/10视频/10音频、4–30秒。Mini时长仍需真实渠道验证。
- 由中间件模型目录下发数量、分辨率、比例、时长、首尾帧、纯音频支持，画布参数面板与连线即时校验；后端和插件再校验。超额明确提示，不截断素材。
- 原价按“计费模式 × 分辨率 × 有无参考视频”存储，单位CNY/1M Token。总量模式每档一个价，分项模式每档输入、输出两个价；有无参考视频与输入/输出是独立维度。画布后台按原价倍率和每元算力换算，或逐档分别设置固定算力/1M Token。宣传标签和备注不参与计费。
- 四个模型初始停用，参考价须管理员核对确认；模型能力/原价版本变化后画布同步会撤下该型号，需核对零售价后重新发布。新模型也是默认未发布。
- 发布中间件模型前须停用旧渠道里的同名模型，避免旧的全局型号价格与新 Token 价格冲突。

## 用户任务与账务

1. 浏览器先准备附件并请求服务端报价。报价绑定用户、请求参数、能力版本、计费模式及单价/预扣数量；分项模式冻结输入价、输出价、输入预扣量、输出预扣量，5分钟有效。
2. 画布后端在同一数据库事务中创建任务、扣减可用算力、写预扣流水。总量推荐预扣50万Token；分项默认输入25万加输出25万，按各自单价求金额。画布预扣数量可在中间件配置，NewAPI插件自身预扣目前固定上述数量，两套额度独立；预扣不是最终费用上限。
3. 持久化任务由服务端提交，浏览器关闭不影响继续处理。同一用户请求ID映射为唯一服务端ID；重试恢复同一任务，不能重复预扣或生成。
4. 总量模式将实际Token乘已锁定的总量单价；分项模式计算`输入Token × 输入单价 / 1000000 + 输出Token × 输出单价 / 1000000`。以十进制有理数先合计，再统一half-up到0.01算力，不能分别舍入后相加，也不能再次加收总量费用。预扣多的退回，少的补扣。
5. 补扣余额不足进入`pending_balance`；不伪装已付清，不把余额扣成负数。新网关任务被阻止，充值后后台重试差额；重复轮询不重复入账。
6. 完成有视频但缺当前模式所需的有效用量时保留结果并待结算，不把预扣量当成实际量。输入/输出必须成对返回，允许真实零；两组别名冲突、总和不一致、字符串或非法数量都等待核对。API实际分项为null代表未取得、0代表真实零。提交超时/5xx进入未知状态，继续按原请求查询，禁止盲目重发到供应商。
7. 明确失败、没有用量且中间件标记`not_billable`时才释放预扣；中间件标记`usage_available`且实际用量通过校验时才允许结算，包括有计费用量的失败任务。`pending_usage`或未知状态即使带有部分看似完整的数字也不能结算或退款。该情况需在渠道上线前以真实返回验证。
8. 已提交渠道任务暂不能真正取消；前端提示后台继续，不能把本地停止轮询当作供应商取消或退款。任务账务记录不随10分钟普通任务清理而删除；存在未结算任务的账号不能删除。

### 分项启用前提

上游必须真实返回完整`usage.input_tokens/output_tokens`或`usage.prompt_tokens/completion_tokens`；同时返回两组时必须逐项一致。总数可省略，但给出时须等于两项之和。仅返回`total_tokens`和`completion_tokens`不满足分项契约，这类模型继续使用总量模式。新增插件能力不代表四个Seedance型号已确认支持真实分项。

例如输入10.35、输出20.70算力/百万Token：预扣25万输入+25万输出为7.76算力，完成10万输入+20万输出为5.18，退2.58；若完成20万输入+40万输出为10.35，补2.59。这里是待验证的合成演示价格，不能当作供应商实际报价。

公开`gatewayModels.sale`及`modelCosts`随模式下发对应单价和两项预扣量。`modelCosts.credits/reserveCredits`只代表全部价格档位最大预扣概览，实际生成读取报价；不得按视频秒数再乘，也不得把输入/输出价格展示为单一总价。

## 素材与结果

- 普通公网链接直接传入中间件；浏览器blob、本地缓存、平台鉴权链接先经登录接口上传为任务临时素材。
- 临时素材存放在服务器`data/gateway-inputs`，带72小时签名链接，单文件256MB、每账号临时文件1GB限制。它不自动进入账号素材库、不重复占个人永久空间额度。启动后每小时及上传时清理过期临时文件；平台磁盘仍需监控。
- URL交给供应商拉取；本次不做供应商素材ID、明星库、Base64协议、视频edit/extend模式。
- 视频结果提供按账号鉴权的内容代理，沿用画布当前浏览器/账号素材库保存偏好。供应商临时结果链接不能当作永久存储承诺。

## 配置步骤

原服务器入口：中间件管理 `https://wx.7cloudvps.com/model-gateway-admin`（另保留HTTPS8088）；画布发布与售价 `https://wx.7cloudvps.com/admin/model-gateway`。画布内部连接及素材域名已配置，管理员密钥通过本机私有访问说明交付，不写入仓库。

1. New API：按[插件说明](../../integrations/new-api/README.md)上传0.2.2 `plugin.js`，保留相同key与路由，绑定任务插件渠道。先配置按`billing_mode`分支的任务用量表达式，再开放分项请求；旧tokens-only表达式不能用于分项。NewAPI美元表达式与人民币原价须明确换算，折扣只应用一次。
2. 中间件：打开独立管理页`/admin`，用管理员密钥登录，添加“我的New API”渠道，地址和Key填用户的NewAPI；原生路径使用`/xiaomeng-newtoken/api/v3/contents/generations/tasks`。核对能力，选择有真实用量依据的计费模式，按分辨率及有无参考视频填写总价或输入/输出两价与预扣量，更新版本后发布。适配器发送`billing_mode`给插件，插件转发NewToken前删除该控制字段并持久化模式。
3. 画布后台“模型中间件”：配置内部中间件URL和独立API连接密钥、画布HTTPS素材域名；同步模型。检查当前模式下的倍率或每个分辨率/参考视频档位售价、名称/宣传标签/备注后发布。
4. 小额联调：固定720p/9:16，先无参考素材4秒，再图片/参考视频，逐项核对实际输出尺寸、usage、预扣流水、差额流水、余额和唯一任务ID。1080p/横屏作为本地拒绝负例。没有用户填写的渠道信息之前不调用付费模型。

## 分组与多规格扩展

当前模型弹窗读取已发布目录的分组、名称、能力和售价，真实分组发布后显示筛选入口。P5已支持一个标准型号配置多个规格与上游路由，各规格独立配置能力和价格；原四个专用插件型号继续固定720×1280，不自动改变已配置渠道。

当前结构为：标准模型（Seedance 2.0）→展示分组（稳定官方/特价/特殊）→规格（分辨率、比例、时长、素材上限）→服务端真实路由（渠道、适配器、上游ID）。归属由管理员确认，不能根据模型名称猜测；Fast、Mini与2.5仍是独立型号。中间件管理接入能力和原价，画布后台管理展示分组、售价与宣传信息。

选择分辨率只展示对应规格的比例和能力，不将不同规格能力简单求并集。后台唯一解析规格后报价并锁定ID、revision、路由和价格；不做跨分组自动切换。更换模型保留素材与提示词，超出数量时提示调整而不是自动删连接。Token总量/分项、按秒、按成功次和同标准名多规格映射已实现；同协议新增配置无需重建容器，新供应商协议仍需开发部署适配器。当前协议边界及真实渠道验收见[短剧制作路线P5](short-drama-production.md#5-标准模型与多规格路由)。

## 验收与边界

初版历史验证：平台2项、网关6项及其2个幂等子例、插件0.1.0的11项曾在禁用网络的隔离环境通过，覆盖总Token金额、两分辨率价格、请求幂等、差额退补、缺失用量、失败释放、余额不足补扣。原服务器完成过画布与中间件部署、后台同步和鉴权验证。具体记录见[待测试](../progress/pending-test.md)。

此前分项实现已随`split-5c917bd9159d`部署，构建及线上服务检查通过；备份与数据校验记录见[待测试](../progress/pending-test.md)。本轮固定竖屏、模型弹窗及多规格能力已通过集中Go/TypeScript/Bun检查，0.2.2插件Node回归16/16通过；两服务已再次构建并部署`production-0df20ae25d24`，双库完整性与原记录/媒体保留核对通过。团队空列表分页另有界面修正，待最终镜像复核。真实渠道数量为0，未进行付费生成；预置模型首次设置须显式选择计费模式。真实输出规格、供应商分项返回、预扣退补与最终计价仍待配置后联调，NewAPI实际导入激活也需确认。

New API宿主有任务超时处理，插件不能覆盖宿主全部策略；画布钱包独立保存账务状态，不使用New API余额变动重复收取用户费用。本专用插件仅支持上述四模型固定竖屏；中间件另有Seedance原生任务协议及NewToken第三方`/v1/videos`的`reference_*`按秒适配器，不等同于任意供应商自动兼容。同一协议调整渠道/价格/能力无需重建容器，新增不同协议需新增适配器及对应验证。
